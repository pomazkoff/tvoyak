# Твояк

«Твояк» — веб-викторина для компании в духе «Своей игры». Ведущий открывает комнату на ноутбуке или телевизоре, игроки и зрители заходят с телефонов по QR-коду или четырёхбуквенному коду. Приложение ставить не нужно, аккаунты не нужны.

Ведущий сам не играет. Это либо человек в комнате, либо бот. Бот читает вопрос голосом браузера (Web Speech API) и сам засчитывает ответ. Живой ведущий может поправить вердикт с экрана.

## Что уже есть

- Комната, лобби и список игроков по Supabase Realtime. От 2 до 10 игроков, плюс зрители.
- Поле 6×5: раунд 1 стоит 100–500, раунд 2 — 200–1000. В каждом раунде 1–2 «кота в мешке».
- Кто выбирает ячейку, жмёт её на телефоне. Вопрос виден на экране ведущего, кнопка открывается после чтения.
- Первый по серверному времени (`clock_timestamp()`) пишет ответ. Верный даёт стоимость и право выбора, неверный всегда снимает стоимость, кнопка открывается остальным. Если никто не взял вопрос, эталон показывают всем.
- «Кота» отдают другому игроку, он отвечает один.
- Финал: тайные ставки только у тех, у кого больше нуля очков.
- Проверка: нормализация, нечёткое сравнение, при `ANSWER_CHECK_USE_LLM=true` — OpenRouter.
- Пул примерно из 150 вопросов. Эталон не уходит на телефоны, пока ячейка не сыграна.

Сроки на сервере: 15 секунд на кнопку, 20 на обычный ответ, 25 на «кота», 60 на ставки, 45 на финальный ответ.

Вопрос может быть картинкой, видео или музыкой. Ролик — YouTube с началом и концом, если он не открылся, плеер пробует VK Video и затем Rutube. У музыки бывает шторка: картинки не видно, звук идёт. У живого ведущего есть галочка «Трек включает ведущий».

## Правила, которые уже лежат в схеме

- Шесть категорий и пять стоимостей. Первый раунд: 100–500, второй: 200–1000.
- Неверный ответ всегда снимает очки. Счёт может уйти в минус.
- «Кот в мешке» отдаётся другому игроку, не тому, кто открыл ячейку.
- Финал играется со скрытыми ставками.
- Версия в `game_states.version` растёт на каждом изменении, чтобы клиенты не затирали друг друга.

## Локальный запуск

Нужны Docker, Node.js 20.9 или новее и [Supabase CLI](https://supabase.com/docs/guides/local-development/cli/getting-started).

```bash
npm install
supabase start
supabase status -o env
cp .env.example .env.local
```

Из вывода `supabase status -o env` перенесите в `.env.local`:

| В статусе          | В `.env.local`              |
| ------------------ | --------------------------- |
| `API_URL`          | `SUPABASE_URL`              |
| `ANON_KEY`         | `SUPABASE_ANON_KEY`         |
| `SERVICE_ROLE_KEY` | `SUPABASE_SERVICE_ROLE_KEY` |

`OPENROUTER_API_KEY` и `OPENROUTER_MODEL` для лобби не нужны. Service role остаётся только на сервере.

```bash
npm run dev
```

Откройте http://127.0.0.1:3000 и создайте комнату. На экране ведущего появятся код и QR, список игроков обновляется сам.

Телефон в той же сети не откроет `localhost`. Запустите сервер так:

```bash
npm run dev -- -H 0.0.0.0
```

Зайдите в браузер ведущего по `http://<адрес-компьютера>:3000`. QR соберётся из этого адреса.

Дальше на телефоне или во второй вкладке откройте `/play/КОД`, введите имя и роль. Ник появится у ведущего без перезагрузки. «Ответить» в лобби отвечает, что вопрос ещё не открыт, и показывает серверное время.

Тот же сценарий против локальной базы:

```bash
npm run verify:lobby
```

Скрипт создаёт комнату, сажает 10 игроков, проверяет отказ одиннадцатому, зрителя, что anon не видит эталон ответа и секреты, и что из двух одновременных нажатий побеждает более раннее серверное время. В конце тестовая комната удаляется.

## Проверка ответа

```bash
curl -s http://127.0.0.1:3000/api/answer-check \
  -H 'content-type: application/json' \
  -d '{"given":"Ёлка!","expected":"елка"}'
```

```json
{
  "correct": true,
  "method": "exact",
  "similarity": 1,
  "llmUsed": false,
  "scoreEffect": "add"
}
```

Сначала текст нормализуется: регистр, `ё` → `е`, кавычки, дефисы, лишние пробелы. Потом нечёткое сравнение. Если ответ близкий, но не достаточно, и в окружении `ANSWER_CHECK_USE_LLM=true` (или `1`), сервер спрашивает модель через OpenRouter. Без флага, ключа или модели вызова нет. `scoreEffect: "subtract"` значит, что ошибка снимает очки; сами очки в M0 ещё не пишутся в счёт.

Это заглушка: эталон приходит в теле запроса. В игре он останется в базе, клиент его не увидит.

Тесты нормализации:

```bash
npm test
```

## Скрипты

- `npm run dev` — разработка
- `npm run build` и `npm start` — сборка
- `npm test` — нормализация и нечёткое сравнение
- `npm run lint` — ESLint
- `npm run format` — Prettier

После правки `.env.local` перезапустите `npm run dev`: URL и anon-ключ попадают в браузерный бандл при сборке страницы.

## Миграции Supabase

Уже применённый каркас:

- `supabase/migrations/20261028120000_init.sql`

Дальше строго по имени файла:

- `supabase/migrations/20261028200000_gameplay.sql` — ход игры, секреты ответов, представление `question_board`
- `supabase/migrations/20261028200100_question_bank.sql` — пул вопросов
- `supabase/migrations/20261028210000_media.sql` — картинка, видео, музыка, шторка, «трек включает ведущий»
- `supabase/migrations/20261028210100_media_questions.sql` — медиа-вопросы
- `supabase/migrations/20261028220000_packs.sql` — пачки и протоколы проверки

Сборка пачки: `POST /api/cron/build-pack` с заголовком `x-admin-token: $ADMIN_TOKEN` или `Authorization: Bearer $CRON_SECRET`. Раз в неделю то же самое вызывает Vercel Cron (`vercel.json`). Без `OPENROUTER_API_KEY` или `OPENROUTER_MODEL` пачка записывается со статусом `failed` и ошибкой `openrouter_missing`, процесс не падает. Готовую пачку смотрят и принимают на `/admin`.

Локально их подхватит `supabase db reset` или `supabase migration up`. На уже живом проекте выполните файлы в SQL Editor или через Management API в этом порядке. В конце gameplay и media есть `notify pgrst`.

## Деплой на Vercel и Supabase

1. Создайте проект на [supabase.com](https://supabase.com).
2. Привяжите CLI и накатите миграции из `supabase/migrations`:

```bash
supabase login
supabase link --project-ref <ref>
supabase db push
```

Миграция добавляет `players` и `game_states` в публикацию `supabase_realtime`. В кабинете это Database → Publications: обе таблицы должны быть в `supabase_realtime`.

3. В Project Settings → API скопируйте URL, anon key и service_role key.
4. Импортируйте репозиторий в Vercel и задайте переменные:

- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`
- `OPENROUTER_API_KEY`
- `OPENROUTER_MODEL` — недорогая модель, например `google/gemini-2.5-flash`
- `ANSWER_CHECK_USE_LLM` — `true`, если спорные ответы нужно отдавать модели

Не создавайте `NEXT_PUBLIC_`-копии service role. Anon-ключ и URL и так попадают в браузер: без них телефон не подпишется на лобби. После смены этих двух значений проект нужно пересобрать.

5. Задеплойте сайт, создайте комнату и зайдите с телефона по QR.

## Задания с картинками

Шесть тем: «Ребусы», «Эмодзи-шифр», «Найди лишнее» (SVG собирается на лету в `/api/media/image/[id]` из `picture_spec`), «По фрагменту», «Размытое фото», «Логотипы» (свободные файлы Wikimedia Commons, показываются через прокси с эффектом). Картинка и эффект показываются только на экране ведущего; на телефонах — «Смотрите экран ведущего». Время раскрытия (`reveal_seconds`) прибавляется к окну кнопки «Ответ». Картиночные задания (одобренные, `enabled`) доступны во всех комнатах.

Седьмая тема — «Детский рисунок»: наивный рисунок «как у ребёнка лет семи» по мотивам известного фильма или мультфильма, ответ — название (варианты — оригинальное и русское, без года). Рисунки нарисованы ИИ (без текста, надписей и логотипов, не повторяют постер) и лежат в `public/pictures/k/` под случайными именами — прокси `/api/media/image/[id]` перенаправляет на файл, имя ответа не выдаёт. Картинка проявляется из лёгкого размытия за 10 секунд. Список заданий и сборка миграции — `scripts/picture-tasks/kids.ts`; эти рисунки — фан-арт по чужим персонажам, для публичного/коммерческого запуска их стоит перепроверить.

Правила генерации и проверки — `src/lib/pictures/generate.ts` и `validate.ts`; банк — `scripts/picture-tasks/bank.ts`, миграция собирается `npx tsx scripts/picture-tasks/build-migration.ts` (проверяет лицензию и доступность каждого файла).

### Ревью картинок

`/admin/pictures` показывает все картиночные задания банка по форматам: картинка целиком, превью эффекта, ответ, варианты, атрибуция и переключатель «оставить/убрать». Выбор хранится в `question_bank.enabled` (по умолчанию `true`), `start_game` берёт картиночные задания только с `enabled`. Вход — тем же `ADMIN_TOKEN`, что и `/admin`, или ссылкой `/api/admin/login?token=…&next=/admin/pictures`. Необязательный `ADMIN_REVIEW_TOKEN` пускает только на ревью картинок.
